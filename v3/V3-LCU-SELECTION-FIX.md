# v3 LCU 英雄轮询修复记录

日期：2026-09-01

## 用户现象

- League Client 已选择人马（英雄编号 `120`），软件偶发跳到恶魔小丑（英雄编号 `35`）。
- 软件同步一次后，700 毫秒轮询会持续把界面拉回客户端英雄，导致无法手动浏览其他英雄。

## 根因

1. LCU 的 `localPlayerCellId=0` 是有效的本地槽位。旧代码使用 `> 0` 判断，错误地把槽位 0 当成“没有本地槽位”，随后可能读取其他玩家的 pick action。
2. `/lol-gameflow/v1/session` 在 `Lobby` 中可能保留上一局或其他玩家的英雄。旧代码会把单一候选当成本地玩家，缺少明确身份校验。
3. 每次轮询只要 LCU 英雄与当前界面不同就重新同步，因此用户手动选择其他英雄后会被同一个旧值反复覆盖。

## 修复内容

- 正确区分“字段不存在”和合法的槽位 `0`，pick action 只接受本地槽位。
- gameflow 只在 `ChampSelect`、`GameStart`、`InProgress`、`Reconnect` 阶段参与回退。
- gameflow 候选必须通过 `summonerId` 或 `isLocalPlayer` 明确匹配当前用户；不再用“只有一个候选”推断本地玩家。
- 新英雄和皮肤编号必须连续采样两次才成为稳定结果，单次异常编号会被忽略。
- 每个实际客户端英雄变化只同步界面一次；同一个稳定值后续轮询不再覆盖用户的手动浏览。
- 应用日志新增候选等待、稳定接受、保持不变及目录缺失原因，包含来源、英雄编号、皮肤编号、阶段和采样次数。

## 回归验证

测试工程：`tests/V3SelectionRegression/V3SelectionRegression.csproj`

覆盖场景：

- 本地槽位 0 的人马不会被其他槽位的小丑覆盖。
- `Lobby` 的残留 gameflow 选择不会进入界面。
- 无法确认本地召唤师时，gameflow 单一候选不会被采用。
- `ChampSelect` 中明确匹配本地召唤师的 gameflow 选择仍可正常同步。
- 单次英雄采样不切换界面。
- 连续两次相同采样只同步一次，后续轮询不干扰手动浏览。
- 瞬时错误英雄不会覆盖已稳定英雄，真实的新英雄连续出现后可以正常同步。

验证结果：7 个回归场景全部通过；`dotnet build v3/CskinNative.csproj --configuration Release --no-restore` 为 0 警告、0 错误。
